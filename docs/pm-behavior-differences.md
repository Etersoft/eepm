# Различия в поведении пакетных менеджеров

## Разрешение конфликтов и автоматическое удаление пакетов

### dnf (Fedora, RHEL, CentOS)

| Флаг | Поведение |
|------|-----------|
| без флагов | Откажется устанавливать при конфликте, предложит добавить `--allowerasing` |
| `--allowerasing` | Разрешает удаление конфликтующих пакетов для установки новых |

**Текущее поведение epm:** использует `--allowerasing` по умолчанию в `epm install`.

### apt-get (Debian, Ubuntu, ALT Linux)

| Режим | Поведение |
|-------|-----------|
| интерактивный | Показывает список пакетов для удаления, спрашивает подтверждение |
| с `-y` | Автоматически соглашается на удаление без подтверждения |

**Нет эквивалента `--allowerasing`** — apt всегда предлагает решение с удалениями как часть плана установки.

**Текущее поведение epm:** передаёт `-y` при `--auto` или неинтерактивном режиме.

### yum (старые RHEL/CentOS)

Не поддерживает `--allowerasing`. Поведение аналогично dnf без этого флага.

### zypper (openSUSE)

| Флаг | Поведение |
|------|-----------|
| без флагов | Предлагает решения конфликтов интерактивно |
| `--force-resolution` | Принудительно разрешает конфликты |

### pacman (Arch Linux)

| Флаг | Поведение |
|------|-----------|
| без флагов | Откажется при конфликте |
| `--overwrite` | Перезаписывает конфликтующие файлы |

### urpmi (Mageia, ROSA)

| Флаг | Поведение |
|------|-----------|
| `--auto` | Автоматически разрешает конфликты |
| `--allow-nodeps` | Игнорирует зависимости |

## Рекомендации

1. **Безопасное поведение по умолчанию**: не удалять пакеты автоматически для разрешения конфликтов
2. **Явный флаг для разрешения**: `epm install --allow-erasing` или аналог
3. **Информирование пользователя**: показывать что будет удалено перед действием
